HC-SR501、GY-302/BH1750、DHT22/AM2302 多节点接入 ESP32-C6 并发送至战舰 V3 调研报告

日期：2026-05-25 · 对象：ESP32-C6-WROOM-1 多采集节点、正点原子 ATK-战舰 STM32F103ZET6 V3
核心结论：单块 ESP32-C6-WROOM-1 可以同时接入 HC-SR501、GY-302/BH1750 和 DHT22/AM2302，并通过串口把数据发给战舰 V3。两块或 N 块同构采集板不建议裸 TTL UART 并线，推荐每块 ESP32-C6 增加 3.3V RS485 收发器，组成主站轮询的多点总线。

可行 单节点采集

BH1750 使用 I2C，AM2302 使用单总线，HC-SR501 使用数字输入，接口互不冲突。统一 3.3V 逻辑可降低电平风险。

推荐 多节点 RS485

每个 ESP32 节点通过 MAX3485、SP3485、ADM3485 等 3.3V RS485 收发器接入 A/B 总线，由战舰 V3 或 ESP32 网关轮询。

禁止 TX 直接并线

多块 ESP32 的 TTL TX 不能直接并到战舰同一个 RX。异常启动、日志输出或同时发送都会造成冲突。

默认 ASCII 轮询帧

先使用易调试文本帧：@Q,ID=03*CS 请求，@D,ID=03,PIR=1,LUX=123.4,T=25.1,H=60.2*CS 应答。

不同 ESP32-C6-WROOM-1 开发板的排针物理位置不一样，同一个 GPIO6 可能在左排、右排或扩展座上。因此本图不按板子外形位置画，而按板上丝印名画。实际接线时先在开发板排针旁找到 3V3、5V/VBUS、GND、GPIO6、GPIO7、GPIO10、GPIO11、GPIO18、GPIO20、GPIO21 这些丝印，再按表插线。

2.5 RS485 多节点到战舰 V3 接线示意图

RS485 图也不要按节点在图里的左右位置找开发板针脚。实际做法是：每块 ESP32 采集板先按 2.2 节完成本地传感器接线，然后只把这块板的 RS485 模块 A、B、GND 接到同一条总线。SVG 版作为附件保留：rs485-multinode-warship-v3-wiring.svg。

从主站到最后一个节点拉一条三线主干：

主站 RS485 A  ==========================================  节点末端 A
主站 RS485 B  ==========================================  节点末端 B
主站 GND      ==========================================  节点末端 GND
                 |                         |
                 |                         |
              节点 01                   节点 02 ... 节点 N
              RS485 A 接 A              RS485 A 接 A
              RS485 B 接 B              RS485 B 接 B
              RS485 GND 接 GND          RS485 GND 接 GND

只在这条主干的两个物理端点加 120Ω：
  第一个端点：A 与 B 之间 120Ω
  最后一个端点：A 与 B 之间 120Ω
  中间节点不要加 120Ω

方案 A：战舰 V3 做主站
  战舰 USART_TX -> 主站 RS485 DI
  战舰 USART_RX <- 主站 RS485 RO
  战舰 GPIO     -> 主站 RS485 DE 和 /RE
  主站 RS485 A/B/GND -> 三线主干 A/B/GND

方案 B：ESP32 网关做主站
  ESP32 网关 RS485 A/B/GND -> 三线主干 A/B/GND
  ESP32 网关 UART_TX -> 战舰 USART_RX
  ESP32 网关 UART_RX <- 战舰 USART_TX，可选
  ESP32 网关 GND     -> 战舰 GND
动作从哪里接接到哪里说明
1主站 RS485 A节点 01 A、节点 02 A、直到节点 N A一条连续主干，节点短支线接入。
2主站 RS485 B节点 01 B、节点 02 B、直到节点 N B所有 B 接同一条 B。
3主站 GND所有节点 RS485 GND建议布参考地，降低共模问题。
4第一个物理端点 A/B120Ω 电阻只装在总线端点。
5最后一个物理端点 A/B120Ω 电阻中间节点不装终端。
6主站侧偏置电阻或模块偏置跳帽偏置只启用一处。

如果 A/B 接反，通常不会烧坏，但通信不通。表现为主站一直超时；此时先只对调一侧 A/B 测试。

3. 两块 ESP32 与 N 块 ESP32 的拓扑分析

不推荐：多块 ESP32 TTL TX 并接

TTL UART 是点对点接口。两块 ESP32 的 TX 不能直接并到战舰 V3 同一个 RX。当两块板同时发送时会出现冲突；即使软件错峰，复位、异常启动、日志输出也可能抢占线路。

可用但扩展差：战舰 V3 多 USART 分别接入

两块 ESP32 可分别接战舰 V3 的两个 USART，但每增加一块 ESP32 就要新增一个 USART，扩展到 N 块很快受限。

推荐：RS485 多点总线

RS485 适合多节点、较长距离和抗干扰需求。所有 ESP32 采集节点挂在同一对 A/B 差分线上，由一个主站控制发送时机。

  • 总线拓扑采用一条主干线，避免星型长分支。
  • A/B 总线两端各放一个 120Ω 终端电阻；短线调试可预留跳帽。
  • 偏置电阻只在主站侧或总线一处配置。
  • 建议布线为 A、B、GND 三线；中长距离用双绞线或屏蔽双绞线。
  • 每块 ESP32 节点 ID 唯一，只有被点名时才打开 DE 发送。

4. 主站拓扑方案

方案 A：战舰 V3 直连 RS485，作为主站

战舰 V3 的一个 USART 接 3.3V 或与 STM32 IO 兼容的 RS485 收发器，收发器的 A/B 接总线。战舰 V3 轮询节点 ID，ESP32 节点只在收到自己 ID 的请求后应答。这是推荐落地方案。

方案 B：ESP32 网关转发给战舰 V3

增加一块 ESP32 作为网关：网关侧通过 RS485 轮询所有采集节点，再把汇总结果通过 TTL UART 发给战舰 V3。它适合战舰端代码想保持简单，或后续要 Wi-Fi、缓存、Web 调试页面的场景。

5. 协议方案分析

默认推荐：主站轮询

主站按节点 ID 逐个发送请求，从站收到匹配 ID 后应答。这个方式最适合半双工 RS485，因为任意时刻只有一个设备发送。

请求：@Q,ID=03*CS\r\n
应答：@D,ID=03,PIR=1,LUX=123.4,T=25.1,H=60.2*CS\r\n
字段含义
@Q查询帧，主站发送。
@D数据帧，从站应答。
ID节点 ID，建议 01-32。
PIRHC-SR501 触发状态，0 或 1。
LUXBH1750 光照值，单位 lux。
TAM2302 温度，单位摄氏度。
HAM2302 湿度，单位 %RH。
CS校验，可用 XOR 或 CRC8；正式使用应启用。

2-8 个节点、房间或实验室近距离布线时，稳定优先用 9600 bps，短线调试可用 115200 bps。每个节点请求后等待 100-300 ms，超时记录离线并继续轮询下一个节点。

可用但不默认：定时主动上报

每个节点按固定周期主动发送数据，节点之间用时间片错峰。这个方案需要随机退避、重发、冲突检测或主站确认机制，不作为默认。

仅适合临时调试：一板一串口

每块 ESP32 独占战舰 V3 一个 UART，协议最简单，但扩展性最差。两块以内可以用于临时验证，N 块部署不建议采用。

7. 验证清单

7.1 上电前检查

  • 万用表测 3.3V 与 GND，确认没有短路。
  • 万用表测 5V 与 GND，确认没有短路。
  • 只给 HC-SR501 上电时测 OUT，高电平应约为 3.3V；若 OUT 为 5V，需要加分压或电平转换后再接 ESP32。
  • 确认 GY-302 和 AM2302 的 VCC 接 3.3V，不接 5V。
  • RS485 总线未接主站前，确认每个节点的 DE 默认低电平，避免上电后驱动总线。

7.2 单节点验证

  • I2C scanner 能发现 BH1750，默认地址通常为 0x23。
  • AM2302 连续读取 5 次，温湿度值合理，读取间隔不小于 2s。
  • HC-SR501 触发时 GPIO10 能从 0 变 1，保持时间符合模块旋钮设置。
  • ESP32 串口可输出一行数据，例如 PIR=1,LUX=123.4,T=25.1,H=60.2。

7.3 两节点/N 节点验证

  • 每个 ESP32 节点 ID 唯一，主站能分别轮询两个节点。
  • RS485 DE/RE 控制正确：节点未被请求时不驱动总线。
  • 断开其中一个节点，其余节点仍可正常响应。
  • 同一条 A/B 总线上只在两端启用 120Ω 终端。
  • 主站记录超时、校验失败和节点恢复上线事件。

7.4 战舰 V3 验证

  • 战舰 V3 能通过 TTL UART 或 RS485 收发器接收 9600 8N1 数据。
  • 若使用方案 A，战舰 V3 能按 ID 轮询并解析多个节点应答。
  • 若使用方案 B，ESP32 网关能汇总 RS485 数据并以普通 UART 文本发送给战舰 V3。

7.5 最小可执行实验顺序

  1. 只接 ESP32-C6、BH1750、AM2302、HC-SR501，先不接 RS485，确认三类数据都能从 ESP32 调试串口打印。
  2. 接一个 ESP32 节点到 RS485 模块，使用 USB-RS485 转换器或战舰 V3 主站发送 @Q,ID=01*CS，确认能收到 @D,ID=01,...。
  3. 加入第二个 ESP32 节点，配置不同 ID，例如 02；主站按 01、02 轮询，确认应答不会互相串扰。
  4. 在 RS485 物理两端启用 120Ω 终端，中间节点不要启用终端。
  5. 断开节点 02，确认主站只记录 02 超时，节点 01 继续正常。
  6. 把主站从 USB-RS485 换成战舰 V3 或 ESP32 网关，保持相同 9600 8N1 与同一帧格式。

8. 最终建议

  1. 单 ESP32 节点先完成三传感器采集。
  2. 增加 3.3V RS485 收发器，完成两个节点轮询。
  3. 先用 ASCII 帧调试，稳定后再决定是否切换 Modbus RTU。
  4. 默认战舰 V3 直连 RS485；如果战舰端软件复杂度过高，再加入 ESP32 网关。
