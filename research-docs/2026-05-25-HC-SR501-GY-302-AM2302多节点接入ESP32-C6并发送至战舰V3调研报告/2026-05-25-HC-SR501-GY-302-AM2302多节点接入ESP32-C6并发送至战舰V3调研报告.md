# HC-SR501、GY-302/BH1750、DHT22/AM2302 多节点接入 ESP32-C6 并发送至战舰 V3 调研报告

日期：2026-05-25

## 1. 结论摘要

单块 ESP32-C6-WROOM-1 可以同时接入 HC-SR501 RD-624 人体红外模块、GY-302/BH1750 光照模块、DHT22/AM2302 温湿度模块，并把处理后的数据通过串口发送给正点原子 ATK-战舰 STM32F103ZET6 V3。

如果有两块或更多 ESP32-C6 采集板，且每块板外设完全相同、放置在不同环境，建议把系统设计为“多采集节点 + RS485 总线”。每块 ESP32-C6 通过 3.3V RS485 收发器接入总线，由战舰 V3 或 ESP32 网关作为主站轮询采集节点。不要把多块 ESP32 的 TTL TX 直接并接到战舰 V3 的同一个 RX，这会造成总线冲突和 IO 互相驱动风险。

推荐优先落地方案：

- 每块 ESP32-C6 作为一个独立采集节点，节点 ID 唯一。
- 每块采集节点本地连接三类传感器。
- 每块 ESP32-C6 的 UART 接 MAX3485、SP3485、ADM3485 等 3.3V 半双工 RS485 收发器。
- 战舰 V3 的一个 USART 通过 RS485 收发器直连 A/B 总线，作为主站轮询所有节点。
- 默认协议使用主站轮询 ASCII 帧，稳定优先波特率 9600，短线调试可用 115200。为了避免 HTML/Markdown 查看器把 `$` 当作数学公式分隔符，本报告的 ASCII 帧头统一使用 `@Q` 和 `@D`。

## 2. 关键硬件兼容性

| 模块 | 接口 | 推荐供电 | ESP32-C6 连接 | 兼容性判断 |
|---|---:|---:|---|---|
| GY-302/BH1750 | I2C | 3.3V | SDA=GPIO6，SCL=GPIO7 | 可接。BH1750 是 I2C 数字光照传感器，常用地址 0x23，ADDR 拉高时可为 0x5C。 |
| DHT22/AM2302 | 单总线 | 3.3V | DATA=GPIO11，上拉 4.7k-10k 到 3.3V | 可接。AM2302/DHT22 支持单总线数字输出，采样间隔建议不小于 2s。 |
| HC-SR501 RD-624 | 数字输出 | 5V | OUT=GPIO10 | 可接。模块通常 5V 供电，OUT 高电平约 3.3V；必须与 ESP32 共地。 |
| RS485 收发器 | UART 半双工 | 3.3V | TX/RX/DE/RE 接 ESP32 GPIO | 推荐用于多节点。不要用 5V 收发器直接驱动 ESP32-C6 IO。 |

ESP32-C6-WROOM-1 工作在 3.3V IO 域。外设信号进入 ESP32-C6 时应保证高电平不超过 3.3V IO 容限。GY-302/BH1750 和 AM2302 建议统一使用 3.3V 供电，使 I2C、单总线和上拉电平都落在 ESP32-C6 安全范围内。HC-SR501 需要按模块实测确认 OUT 高电平；常见 HC-SR501 模块输出约 3.3V，适合接 ESP32 输入，但仍建议首次上电前用万用表测量 OUT。

### 3.2 单个 ESP32-C6 采集节点电路示意图

先说明一个限制：不同 ESP32-C6-WROOM-1 开发板的排针物理位置不一样，同一个 `GPIO6` 可能在左排、右排或扩展座上。因此本图不按“板子外形位置”画，而按“板上丝印名”画。实际接线时先在开发板排针旁找到 `3V3`、`5V/VBUS`、`GND`、`GPIO6`、`GPIO7`、`GPIO10`、`GPIO11`、`GPIO18`、`GPIO20`、`GPIO21` 这些丝印，再按表插线。

如果你的开发板丝印写成 `IO6`、`D6`、`G6`，通常对应 `GPIO6`；若不确定，应以开发板原理图或 pinout 图为准。

建议按下面顺序读图：

1. 先接所有 `GND`，让 ESP32、三个传感器、RS485 模块共地。
2. 再接电源：BH1750、AM2302、RS485 接 `3V3`；HC-SR501 接 `5V/VBUS`。
3. 再接信号线：I2C、DATA、OUT、UART、DE。
4. 最后再接 RS485 A/B 总线。

```text

-----------------------             -------------------------------
3V3  ------------------------------> GY-302 VCC
3V3  ------------------------------> AM2302 VCC
3V3  ------------------------------> RS485 VCC

GND  ------------------------------> GY-302 GND

GND  ------------------------------> HC-SR501 GND
GND  ------------------------------> RS485 GND

GPIO10 / IO10 <-------------------- HC-SR501 OUT

GPIO20 / IO20 ---------------------> RS485 DI
GPIO21 / IO21 <-------------------- RS485 RO
GPIO18 / IO18 ---------------------> RS485 DE 与 /RE，并在一起接

HC-SR501 OUT 接 ESP32 前，先用万用表确认高电平约 3.3V。
```

| 功能 | ESP32-C6 引脚 | 外设引脚 | 备注 |

| RS485 UART RX | GPIO21 | RO | 收发器返回到 ESP32。 |

### 3.5 RS485 多节点到战舰 V3 接线示意图

RS485 图也不要按节点在图里的左右位置找开发板针脚。实际做法是：每块 ESP32 采集板先按 3.2 节完成本地传感器接线，然后只把这块板的 RS485 模块 `A`、`B`、`GND` 接到同一条总线。

文本版总线示意图如下；SVG 版作为附件保留：`rs485-multinode-warship-v3-wiring.svg`。

```text
从主站到最后一个节点拉一条三线主干：

主站 RS485 A  ==========================================  节点末端 A
主站 RS485 B  ==========================================  节点末端 B
主站 GND      ==========================================  节点末端 GND
                 |                         |
                 |                         |
              节点 01                   节点 02 ... 节点 N
              RS485 A 接 A              RS485 A 接 A
              RS485 B 接 B              RS485 B 接 B
              RS485 GND 接 GND          RS485 GND 接 GND

只在这条主干的两个物理端点加 120Ω：
  第一个端点：A 与 B 之间 120Ω
  最后一个端点：A 与 B 之间 120Ω
  中间节点不要加 120Ω

方案 A：战舰 V3 做主站
  战舰 USART_TX -> 主站 RS485 DI
  战舰 USART_RX <- 主站 RS485 RO
  战舰 GPIO     -> 主站 RS485 DE 和 /RE
  主站 RS485 A/B/GND -> 三线主干 A/B/GND

方案 B：ESP32 网关做主站
  ESP32 网关 RS485 A/B/GND -> 三线主干 A/B/GND
  ESP32 网关 UART_TX -> 战舰 USART_RX
  ESP32 网关 UART_RX <- 战舰 USART_TX，可选
  ESP32 网关 GND     -> 战舰 GND
```

RS485 总线施工表：

| 动作 | 从哪里接 | 接到哪里 | 说明 |
|---|---|---|---|
| 1 | 主站 RS485 A | 节点 01 A、节点 02 A、直到节点 N A | 一条连续主干，节点短支线接入。 |
| 2 | 主站 RS485 B | 节点 01 B、节点 02 B、直到节点 N B | 所有 B 接同一条 B。 |
| 3 | 主站 GND | 所有节点 RS485 GND | 建议布参考地，降低共模问题。 |
| 4 | 第一个物理端点 A/B | 120Ω 电阻 | 只装在总线端点。 |
| 5 | 最后一个物理端点 A/B | 120Ω 电阻 | 中间节点不装终端。 |
| 6 | 主站侧 | 偏置电阻或模块偏置跳帽 | 偏置只启用一处。 |

如果 A/B 接反，通常不会烧坏，但通信不通。表现为主站一直超时；此时先只对调一侧 A/B 测试。

### 3.6 方案 A：战舰 V3 作为 RS485 主站的逐线接线

| 战舰 V3/STM32 侧 | 主站 RS485 模块 | 说明 |
|---|---|---|
| 3.3V | VCC | 优先使用 3.3V RS485 模块。 |
| GND | GND | 与 RS485 总线 GND、ESP32 节点 GND 建立参考地。 |
| USART_TX | DI | 战舰发送轮询请求。 |
| USART_RX | RO | 战舰接收 ESP32 节点应答。 |
| 任意可控 GPIO | DE 和 /RE | 发送前置 1，发送完成后置 0。 |
| RS485 A | 总线 A | 接所有节点 A。 |
| RS485 B | 总线 B | 接所有节点 B。 |

主站侧建议放置一组 fail-safe 偏置电阻。若购买的 RS485 模块已经带偏置与终端电阻，先只启用主站侧偏置，并只在总线两端启用 120Ω 终端。

### 3.7 方案 B：ESP32 网关转发给战舰 V3 的逐线接线

网关 ESP32 的 RS485 侧按 3.4 节接入 A/B/GND 总线；网关到战舰 V3 使用 3.3V TTL UART：

| ESP32 网关 | 战舰 V3/STM32 | 说明 |
|---|---|---|
| UART_TX | USART_RX | 网关把汇总数据发给战舰。 |
| UART_RX | USART_TX | 可选，战舰需要给网关下发命令时连接。 |
| GND | GND | 必须共地。 |

不要把 ESP32 网关 TTL UART 接到 DB9 RS232 口；若只能使用 DB9 RS232，需要 MAX3232 电平转换。

## 4. 两块 ESP32 与 N 块 ESP32 的拓扑分析

### 4.1 不推荐：多块 ESP32 TTL TX 并接

TTL UART 是点对点接口。两块 ESP32 的 TX 不能直接并到战舰 V3 的同一个 RX。当两块板同时发送时，线路上会出现冲突；即使软件错峰，复位、异常启动、日志输出也可能让某个 TX 抢占线路。这个方案只适合一块 ESP32 对一块战舰 UART 的临时调试，不适合两块以上采集板。

### 4.2 可用但扩展差：战舰 V3 多 USART 分别接入

两块 ESP32 可分别接战舰 V3 的两个 USART，前提是战舰 V3 引出了足够的 TTL 串口且软件分别接收。这种方式接线直观，但每增加一块 ESP32 就要新增一个 USART，扩展到 N 块很快受限。

### 4.3 推荐：RS485 多点总线

RS485 适合多节点、较长距离和抗干扰需求。所有 ESP32 采集节点挂在同一对 A/B 差分线上，由一个主站控制发送时机。

推荐总线规则：

- 总线拓扑采用一条主干线，避免星型长分支。
- A/B 总线两端各放一个 120Ω 终端电阻；短线调试可预留跳帽，不一定一直焊死。
- 偏置电阻只在主站侧或总线一处配置，避免多个节点重复偏置导致负载过重。
- 建议布线为 A、B、GND 三线；中长距离用双绞线或屏蔽双绞线。
- 每块 ESP32 节点 ID 唯一，可用固件配置、拨码开关、NVS 或烧录参数设置。
- 所有从站默认接收，只有被点名时才打开 DE 发送。

## 5. 主站拓扑方案

### 方案 A：战舰 V3 直连 RS485，作为主站

这是推荐方案。战舰 V3 的一个 USART 接 3.3V 或与 STM32 IO 兼容的 RS485 收发器，收发器的 A/B 接总线。战舰 V3 轮询节点 ID，ESP32 节点只在收到自己 ID 的请求后应答。

优点：

- 总线主站就是最终控制板，系统层级少。
- ESP32 采集节点固件一致，部署和扩展简单。
- 战舰 V3 端可直接掌握节点在线状态和数据时序。

注意：

- 战舰 V3 的 STM32F103ZET6 是 3.3V MCU，优先选 3.3V RS485 收发器。
- 不要把 ESP32 TTL UART 直接接到战舰板 DB9 RS232 口。RS232 电平与 MCU TTL 电平不同，必须通过板载或外置电平转换。
- 如果战舰 V3 已有板载 RS485 电路，应按其手册确认对应 USART、方向控制引脚、A/B 接线极性。

### 方案 B：ESP32 网关转发给战舰 V3

增加一块 ESP32 作为网关：网关侧通过 RS485 轮询所有采集节点，再把汇总结果通过 TTL UART 发给战舰 V3。

优点：

- 战舰 V3 只需要处理一个普通串口数据流，软件更简单。
- 网关可增加缓存、重发、离线检测、Wi-Fi 或 Web 调试页面。
- 如果后续改为无线或联网，网关架构更容易演进。

代价：

- 多一块 ESP32 和一份网关固件。
- 网关成为单点故障，需要看门狗和掉电恢复设计。
- 延迟和调试路径比方案 A 略复杂。

## 6. 协议方案分析

### 6.1 默认推荐：主站轮询

主站按节点 ID 逐个发送请求，从站收到匹配 ID 后应答。这个方式最适合半双工 RS485，因为任意时刻只有一个设备发送。

示例 ASCII 帧：

```text
请求：@Q,ID=03*CS\r\n
应答：@D,ID=03,PIR=1,LUX=123.4,T=25.1,H=60.2*CS\r\n
```

字段建议：

| 字段 | 含义 |
|---|---|
| `@Q` | 查询帧，主站发送。 |
| `@D` | 数据帧，从站应答。 |
| `ID` | 节点 ID，建议 01-32。 |
| `PIR` | HC-SR501 触发状态，0 或 1。 |
| `LUX` | BH1750 光照值，单位 lux。 |
| `T` | AM2302 温度，单位摄氏度。 |
| `H` | AM2302 湿度，单位 %RH。 |
| `CS` | 校验，可用 XOR 或 CRC8；调试初期可先打印固定占位，正式使用应启用校验。 |

主站轮询策略：

- 2-8 个节点、房间/实验室近距离：默认 9600 bps，短线调试可用 115200 bps。
- 每个节点请求后等待超时，例如 100-300 ms；超时记录离线并继续轮询下一个节点。
- AM2302 读取不宜过快，从站可本地缓存最近一次有效温湿度，主站轮询时直接返回缓存。
- PIR 是事件型信号，从站可返回当前状态，也可返回最近一个轮询周期内是否触发过。

### 6.2 可用但不默认：定时主动上报

每个节点按固定周期主动发送数据，节点之间用时间片错峰。这个方案不需要主站逐个请求，但节点时钟漂移、复位重启和异常丢包会带来冲突风险。若使用主动上报，必须增加随机退避、重发、冲突检测或主站确认机制。

### 6.3 仅适合临时调试：一板一串口

每块 ESP32 独占战舰 V3 一个 UART，协议最简单，但扩展性最差。两块以内可以用于临时验证传感器数据，N 块部署不建议采用。

### 6.4 可替代协议：Modbus RTU

如果后续需要接工业设备或上位机，可把 ASCII 帧替换为 Modbus RTU。Modbus RTU 自带地址、功能码和 CRC，生态成熟；缺点是调试时不如 ASCII 帧直观。教学、快速验证和串口助手观察阶段，本报告建议先用 ASCII 帧。

## 7. 战舰 V3 串口与电平注意事项

正点原子 ATK-战舰 STM32F103ZET6 V3 使用 STM32F103ZET6，MCU IO 工作在 3.3V 逻辑域。与 ESP32-C6 直接 TTL UART 对接时，两端均应共地，并交叉连接 TX/RX。

单 ESP32 直连战舰 V3 时：

| ESP32-C6 | 战舰 V3/STM32 | 说明 |
|---|---|---|
| TX | USART_RX | ESP32 发送，战舰接收。 |
| RX | USART_TX | 可选，若战舰需要下发命令则连接。 |
| GND | GND | 必须共地。 |

多 ESP32 通过 RS485 接战舰 V3 时：

| 战舰 V3/STM32 | RS485 收发器 | 说明 |
|---|---|---|
| USART_TX | DI | 主站发送请求。 |
| USART_RX | RO | 主站接收节点应答。 |
| GPIO | DE 和 /RE | 半双工方向控制。 |
| GND | GND | 与总线参考地连接。 |
| A/B | A/B 总线 | 注意不同模块 A/B 标识可能相反，调试时可对调验证。 |

严禁把 ESP32 GPIO 直接接到 RS232 DB9 电平口。RS232 电平可能为正负电压，必须经过 MAX3232 等电平转换或使用板上的 TTL 串口/RS485 接口。

## 8. 供电与可靠性建议

- ESP32-C6、BH1750、AM2302、RS485 收发器使用稳定 3.3V，HC-SR501 按模块要求使用 5V。
- 所有模块 GND 必须连接；RS485 多节点建议总线带 GND 参考地，避免共模漂移。
- 每块采集节点应在 3.3V 与 5V 输入处加去耦电容，传感器线较长时增加 TVS 或串联小电阻。
- AM2302 线长较长时降低上拉阻值到 4.7k，并降低读取频率。
- RS485 中长距离布线优先用双绞线，远离电机、继电器和强电线。
- 节点 ID 要有现场可核验方式，例如上电串口打印、标签纸、拨码开关或配置表。

## 9. 验证清单

### 9.1 上电前检查

- 万用表测 3.3V 与 GND，确认没有短路。
- 万用表测 5V 与 GND，确认没有短路。
- 只给 HC-SR501 上电时测 OUT，高电平应约为 3.3V；若 OUT 为 5V，需要加分压或电平转换后再接 ESP32。
- 确认 GY-302 和 AM2302 的 VCC 接 3.3V，不接 5V。
- RS485 总线未接主站前，确认每个节点的 DE 默认低电平，避免上电后驱动总线。

### 9.2 单节点验证

- I2C scanner 能发现 BH1750，默认地址通常为 0x23。
- AM2302 连续读取 5 次，温湿度值合理，读取间隔不小于 2s。
- HC-SR501 触发时 GPIO10 能从 0 变 1，保持时间符合模块旋钮设置。
- ESP32 串口可输出一行数据，例如 `PIR=1,LUX=123.4,T=25.1,H=60.2`。

### 9.3 两节点/N 节点验证

- 每个 ESP32 节点 ID 唯一，主站能分别轮询两个节点。
- RS485 DE/RE 控制正确：节点未被请求时不驱动总线。
- 断开其中一个节点，其余节点仍可正常响应。
- 同一条 A/B 总线上只在两端启用 120Ω 终端。
- 主站记录超时、校验失败和节点恢复上线事件。

### 9.4 战舰 V3 验证

- 战舰 V3 能通过 TTL UART 或 RS485 收发器接收 9600 8N1 数据。
- 若使用方案 A，战舰 V3 能按 ID 轮询并解析多个节点应答。
- 若使用方案 B，ESP32 网关能汇总 RS485 数据并以普通 UART 文本发送给战舰 V3。

### 9.5 最小可执行实验顺序

1. 只接 ESP32-C6、BH1750、AM2302、HC-SR501，先不接 RS485，确认三类数据都能从 ESP32 调试串口打印。
2. 接一个 ESP32 节点到 RS485 模块，使用 USB-RS485 转换器或战舰 V3 主站发送 `@Q,ID=01*CS`，确认能收到 `@D,ID=01,...`。
3. 加入第二个 ESP32 节点，配置不同 ID，例如 02；主站按 01、02 轮询，确认应答不会互相串扰。
4. 在 RS485 物理两端启用 120Ω 终端，中间节点不要启用终端。
5. 断开节点 02，确认主站只记录 02 超时，节点 01 继续正常。
6. 把主站从 USB-RS485 换成战舰 V3 或 ESP32 网关，保持相同 9600 8N1 与同一帧格式。

## 10. 最终建议

如果当前只验证一块 ESP32-C6，三类传感器可以直接接在同一块板上，并用 TTL UART 发给战舰 V3。

如果已经确定会有两块，且后续可能扩展到 N 块，建议从一开始就按 RS485 多节点设计。这样每块采集板硬件和固件保持一致，只需要分配不同节点 ID；战舰 V3 端或网关端负责轮询，后续扩展节点时不需要重新增加战舰串口。

本项目推荐优先实现：

1. 单 ESP32 节点完成三传感器采集。
2. 增加 3.3V RS485 收发器，完成两个节点轮询。
3. 先用 ASCII 帧调试，稳定后再决定是否切换 Modbus RTU。
4. 默认战舰 V3 直连 RS485；如果战舰端软件复杂度过高，再加入 ESP32 网关。
