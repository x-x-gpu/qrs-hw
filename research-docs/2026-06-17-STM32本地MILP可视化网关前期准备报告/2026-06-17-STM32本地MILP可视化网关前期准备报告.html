1. 报告范围

本报告整理我负责的 STM32 本地 MILP 可视化网关在正式开发前的准备过程。队友已经完成 ESP32-C6 多传感器采集节点、RS485 总线连接和战舰 V3 主站轮询显示，因此本阶段的重点不是重新做一套硬件采集，而是在不破坏原有链路的前提下，把 PC 端求解、网页可视化、串口控制帧返回和 STM32 LCD 状态显示接入到同一个仓库中。

本阶段主要解决三个问题：第一，确认课程题目中“智能网关、混合整数规划、可视化与硬件控制”的要求如何落到当前硬件；第二，梳理 qrs-hw 与我原先 stm32_localhost_MILP 目录之间的关系；第三，提前排查烧录口、普通串口、COM 口占用等容易在演示现场踩坑的问题。

2. 项目定位与分工边界

整体系统采用“硬件采集 + PC 求解 + STM32 反馈”的闭环结构。前期准备时我没有直接覆盖队友已经跑通的 stm32-warship-v3-rs485-test/，而是把 MILP 网关作为一个独立副本加入仓库，这样可以保留原始 RS485 主站工程作为对照，也方便老师检查两部分工作的边界。

模块 负责人侧重点 目录 本阶段处理方式

从系统功能上看，队友部分解决“环境数据从哪里来、如何可靠到达 STM32”的问题；我这部分解决“数据到达后如何优化决策、如何可视化、如何把决策返回硬件”的问题。这样分工后，两部分不是并列孤立的 demo，而是可以串成完整的智能网关闭环。

3. 仓库整合原则

整合时采用“并列补充、引用对齐、保留基线”的原则。具体做法如下：

  1. assets/、code/、data/、frontend/ 和 stm32-warship-v3-milp-gateway/ 直接放入 qrs-hw 根目录，避免散落在原来的个人目录中。
  2. stm32-warship-v3-rs485-test/ 不做覆盖，确保队友的 RS485 主站固件仍然能独立编译和演示。
  3. stm32-warship-v3-milp-gateway/ 从 RS485 主站工程派生，保留 LCD、FSMC、USART3 轮询等基础能力，只额外增加 USART1 控制帧入口。
  4. research-docs/ 按日期拆成前期准备、算法设计、接口对齐、演示调试四份报告，避免把所有过程压成一篇流水账。
  5. 每个报告目录下同级保存 Markdown 与 HTML，references/ 只放参考资料、数据手册、网页快照或工程配置，不再把报告 HTML 放进 references/。

这种排布与队友已有报告保持一致：报告正文是老师直接打开阅读的入口，参考资料则作为证据和技术来源放在子目录中。

4. 环境与工具检查

PC 侧尽量使用 Python 标准库完成本地 HTTP 服务和求解演示，降低现场安装依赖失败的概率。只有自动串口转发需要 pyserial，如果现场来不及配置，也可以先用网页生成控制帧，再用 XCOM 或其他串口助手手动发送。

python --version
cd .\code\pc_milp_solver
python .\gateway_milp.py
python .\gateway_server.py

STM32 侧继续使用已有工具链：

arm-none-eabi-gcc --version
openocd --version
cd .\stm32-warship-v3-milp-gateway
make
make flash

前期检查中确认 make 能生成 build/warship_v3_milp_gateway.elf，make flash 通过 OpenOCD 和 ST-Link 下载。曾经出现过 OpenOCD open failed，后来排查发现不是 ELF 文件错误，而是 ST-Link 连接、驱动枚举或板卡供电状态导致 OpenOCD 无法打开调试器。重新插拔并确认供电后可以正常烧录。

5. 串口与烧录口区分

本阶段最重要的硬件认知是：SWD/JTAG 口和 USART 串口不是同一种通道。ST-Link/SWD 负责下载、复位和调试芯片；PC 端要向程序发送普通文本帧，必须连接到 STM32 程序实际初始化的 USART 通道。

通道 作用 是否能接收 @C 控制帧 调试现象
ST-Link / SWD / JTAG烧录固件、调试下载不能make flash 使用它，但 XCOM 发帧无效
USART1 / CH340 或 USB-TTLPC 到 STM32 控制帧可以115200 8N1，收到后返回 ACK
USART3 / RS485STM32 与 ESP32 节点轮询不作为 PC 控制入口用于 @Q、@D 硬件链路

我一开始把 USB 线接到 SWD/JTAG 口后，在 XCOM 中发送 @C 帧没有响应。后来通过 LCD 的 U1 RX 计数和串口 READY 文本确认，必须接到 USART1 对应的 USB 转串口通道，STM32 程序才会收到 PC 发来的普通串口数据。

7. 本阶段产出

本阶段完成了以下准备工作：

  • 明确了 qrs-hw 中两名成员的工作边界和连接方式。
  • 将我的 MILP、网页、协议和 STM32 控制副本按不覆盖原则整合到仓库中。
  • 验证了 PC 端求解脚本、网页服务、STM32 Makefile 和 OpenOCD 烧录链路。
  • 建立了 SWD/JTAG 与 USART 的区分，避免后续把烧录口误当作串口使用。
  • 按队友报告风格拆分后续文档，为算法、接口和演示调试报告打基础。
